# FR-08 and FR-09: System Monitoring & Operational Incident Handling Specifications

## 1. Document Overview

This document specifies the software requirements for **FR-08 (System Monitoring)** and **FR-09 (Incident Handling)** of the **Smart E-Mobility Hub** system for the VNU-HCM Urban Area. It breaks down the high-level capabilities into granular sub-requirements, defines the operational incident taxonomy, outlines system escalation rules, and provides structured Use-Case tables.

---

## 2. Functional Requirements

### FR-08: System Monitoring

- **FR-08.01 – Real-Time Hub Resource Tracking:** The system shall continuously ingest live telemetry data (`src/iot_sim/`) covering vehicle states, battery levels ($SoC\%$), parking slot occupancy, and charging port statuses across all Mobility Hubs in the VNU-HCM network.
- **FR-08.02 – Utilization & Metrics Computation:** The system shall automatically compute real-time capacity utilization percentages and fleet readiness metrics for each individual Mobility Hub and display them on the operator dashboard.
- **FR-08.03 – Capacity Warning & Threshold Alerting:** The system shall flag and visually highlight Mobility Hubs that approach or exceed predefined operational warning thresholds (e.g., parking occupancy $\ge 90\%$) on the operator console.
- **FR-08.04 – Network State Synchronization:** The system shall synchronize all real-time aggregated metrics and telemetry logs with the core domain state management module (`src/core/`).

### FR-09: Incident Handling

- **FR-09.01 – Automated Incident Detection:** The system shall automatically detect operational failures, such as charging hardware faults, IoT communication dropouts, or parking capacity overflows, based on incoming error codes and sensor timeouts.
- **FR-09.02 – Incident Classification & Ticket Generation:** The system shall categorize detected incidents by type and severity level (Low, Medium, High) and automatically generate structured incident tickets into the operator work queue.
- **FR-09.03 – Automated Safety Interlocks:** The system shall execute automated safety responses upon incident detection, such as isolating a faulty charging port or locking out critically low-battery vehicles from the active rental pool.
- **FR-09.04 – Incident Lifecycle Tracking:** The system shall track and update incident ticket statuses through their complete operational lifecycle (`NEW` $\rightarrow$ `IN_PROGRESS` $\rightarrow$ `RESOLVED` $\rightarrow$ `CLOSED`) with complete audit logs.

## 3. Incident Type List

| Incident ID     | Category            | Description                                                        | Severity | Default Trigger Condition                                    |
| :-------------- | :------------------ | :----------------------------------------------------------------- | :------- | :----------------------------------------------------------- |
| **INC-HW-01**   | Hardware / Charger  | Charging point hardware fault or power supply failure.             | High     | Fault code received or power failure detected.               |
| **INC-HW-02**   | Hardware / Sensor   | Parking slot sensor failure or state mismatch.                     | Medium   | Sensor signal lost or state conflict $> 5$ mins.             |
| **INC-CAP-01**  | Capacity / Parking  | Hub reaches $100\%$ parking capacity, blocking vehicle returns.    | High     | Occupied slot counter equals total Hub capacity.             |
| **INC-CAP-02**  | Capacity / Vehicle  | High vehicle deficit at critical locations (e.g., Metro Station).  | Medium   | Available rental vehicle count $< 2$ units at Hub.           |
| **INC-BAT-01**  | Vehicle / Battery   | Vehicle battery drops below critical operating limit ($\le 10\%$). | High     | Telemetry reports battery level $\le 10\%$.                  |
| **INC-COMM-01** | Network / Telemetry | Loss of telemetry stream from a Mobility Hub gateway.              | High     | No telemetry received from Hub for $> 30$ seconds.           |
| **INC-USR-01**  | User / Operational  | Vehicle rental overdue beyond grace period without extension.      | Low      | Active rental duration exceeds reserved time by $> 60$ mins. |

## 4. Draft Escalation Business Rules (BRs)

- **BR-08-01 (Capacity Warning Threshold):** When a Hub's parking occupancy reaches $\ge 90\%$, the system shall mark the Hub as "WARNING" and send a notification to the operator console.
- **BR-08-02 (Critical Capacity Overflow):** When a Hub reaches $100\%$ capacity (`INC-CAP-01`), the system shall mark the Hub as "CRITICAL", temporarily block new parking reservations for that location, and suggest nearby alternative Hubs to users.
- **BR-09-01 (Charger Fault Isolation):** Upon detecting a charger failure (`INC-HW-01`), the system must automatically cut power to the socket, set the port state to `OUT_OF_SERVICE`, notify the user, and generate an urgent incident ticket.
- **BR-09-02 (Unacknowledged Incident Escalation):** If a High-Severity incident remains unacknowledged by an operator for $> 5$ minutes, the system shall escalate the ticket priority to "URGENT" and notify the duty supervisor.
- **BR-09-03 (Low Battery Lockout):** Any vehicle reporting battery level $\le 15\%$ shall be automatically removed from the active rental pool and prioritized for charging.
